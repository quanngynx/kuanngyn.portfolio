# Agentic Pattern Catalog

Use this comparison after [SKILL.md](SKILL.md) identifies candidates. Each linked chapter expands the implementation, trade-offs, failure modes, and composition rules.

| Pattern | Problem / intent; when to use | When not to use | Implementation structure | Trade-offs, failure modes, and interactions |
| --- | --- | --- | --- | --- |
| [Prompt Chaining](chapters/ch01-prompt-chaining.md) | Execute known dependent transformations with validated intermediate results. | Work is independent or the path is unknown. | Contract -> transform -> validate -> persist -> forward. | More calls and propagation risk; compose with Tools, Planning, Parallelization, Reflection. |
| [Routing](chapters/ch02-routing.md) | Select among known handlers, tools, or owners. | The path must be invented or stable rules suffice. | Taxonomy -> selector -> confidence/fallback -> authorized dispatch. | Misroutes are high impact; route to Tool Use without conflating selection and authority. |
| [Parallelization](chapters/ch03-parallelization.md) | Reduce elapsed time for dependency-independent work. | Ordering, shared mutation, or quotas make concurrency unsafe. | Dependency graph -> bounded fan-out -> typed results -> join. | Peak cost, stragglers, partial joins; combine with Multi-Agent only for real role boundaries. |
| [Reflection](chapters/ch04-reflection.md) | Repair an artifact against evidence and explicit criteria. | Defects are unobservable or no revision budget exists. | Produce -> evaluate -> defects -> revise -> re-evaluate. | Self-approval and endless polishing; Evaluation measures while Reflection repairs. |
| [Tool Use](chapters/ch05-tool-use.md) | Reach live data, computation, or side effects. | Deterministic code solves the task or safe authorization is impossible. | Propose -> validate/authorize -> execute -> observe -> record. | Broad authority, bad arguments, duplicate effects; combine with Routing, Guardrails, Recovery. |
| [Planning](chapters/ch06-planning.md) | Discover and revise a path to a known goal. | A stable workflow exists or success is undefined. | Goal/state/constraints -> plan -> step -> observation -> continue/re-plan/stop. | Infeasible plans and endless revision; Goal Monitoring decides whether progress is real. |
| [Multi-Agent Collaboration](chapters/ch07-multi-agent-collaboration.md) | Partition genuine expertise, context, tools, or authority. | Roles are personas or integration ownership is absent. | Role contracts -> topology -> bounded messages -> named integrator. | Coordination bugs and shared blind spots; pair with Parallelization, A2A, Evaluation. |
| [Memory Management](chapters/ch08-memory-management.md) | Preserve governed task, session, user, or durable continuity. | Fresh authoritative evidence should be retrieved. | Typed record -> provenance/scope/expiry -> recall -> conflict policy. | Staleness, poisoning, leakage; Memory preserves temporal state while RAG supplies sources. |
| [Learning and Adaptation](chapters/ch09-learning-and-adaptation.md) | Improve future behavior from repeated evaluated outcomes. | Feedback, baseline, or rollback is missing. | Capture -> filter -> candidate -> offline evaluation -> gated promotion. | Reward hacking and regressions; compose with Memory, Evaluation, HITL. |
| [MCP](chapters/ch10-model-context-protocol.md) | Standardize reusable capability discovery and transport. | Direct functions are simpler. | Host -> client -> authenticated server -> service -> observation. | Discovery is not trust; Tool Use owns invocation control, while A2A delegates agent tasks. |
| [Goal Setting and Monitoring](chapters/ch11-goal-setting-and-monitoring.md) | Bind long-running activity to evidence and terminal states. | Success is immediate and deterministic. | Goal/criteria -> observations -> comparison -> continue/correct/stop. | Proxy gaming and unsupported completion; Planning chooses actions, monitoring judges them. |
| [Exception Handling and Recovery](chapters/ch12-exception-handling-and-recovery.md) | Restore safe state after operational failure. | Prevention or validation removes the issue. | Detect -> classify -> record -> retry/fallback/compensate/escalate -> verify. | Retry storms and duplicate effects; Guardrails prevent, recovery responds. |
| [Human-in-the-Loop](chapters/ch13-human-in-the-loop.md) | Assign consequential judgment to accountable people. | Review adds no expertise or authority. | Trigger -> pause -> evidence -> authenticated decision -> revalidate. | Approval theater and stale decisions; Guardrails set hard bounds around human judgment. |
| [RAG](chapters/ch14-knowledge-retrieval-rag.md) | Ground claims in current, private, attributable evidence. | Supplied context or deterministic query suffices. | Ingest -> retrieve -> rerank -> evidence -> cite -> evaluate. | Bad chunks, stale authority, access leakage; interact with Memory, Routing, Evaluation. |
| [A2A](chapters/ch15-inter-agent-communication-a2a.md) | Delegate tasks across interoperable agent boundaries. | A direct tool, queue, or MCP resource suffices. | Authenticate -> task -> lifecycle -> messages/artifacts -> delivery. | Spoofing, duplicate delegation, protocol drift; Multi-Agent defines the roles. |
| [Resource-Aware Optimization](chapters/ch16-resource-aware-optimization.md) | Meet quality within cost, latency, token, and concurrency budgets. | No budget or quality floor exists. | Budget -> estimate -> strategy -> execute -> measure/degrade. | Proxy optimization and quality collapse; Prioritization chooses what, optimization chooses resources. |
| [Reasoning Techniques](chapters/ch17-reasoning-techniques.md) | Match decomposition, search, computation, or action loops to problem shape. | Direct deterministic execution suffices. | Classify -> technique -> inspectable artifacts -> verify -> stop. | Ritual verbosity and unpruned search; interact with Planning, Reflection, Tools. |
| [Guardrails](chapters/ch18-guardrails-safety-patterns.md) | Enforce policy across input, context, decisions, tools, state, and output. | The concern is only operational recovery. | Threat model -> layered controls -> least privilege -> audit/response. | False positives and prompt-only control; pair with Recovery and HITL without bypassing hard bounds. |
| [Evaluation and Monitoring](chapters/ch19-evaluation-and-monitoring.md) | Measure outcomes, contracts, trajectories, resources, and production behavior. | Success is unobservable. | Cases -> metrics/judges -> traces -> thresholds -> release/alert. | Overfitting, judge bias, vanity metrics; independently measure Reflection and Learning. |
| [Prioritization](chapters/ch20-prioritization.md) | Order competing ready work under limited capacity. | Dependencies dictate the only valid order. | Hard constraints -> factors -> rules/score -> aging -> re-rank. | Hidden weights and starvation; Resource Optimization follows ranking. |
| [Exploration and Discovery](chapters/ch21-exploration-and-discovery.md) | Generate and test valuable unknown alternatives. | A known answer only needs execution. | Evidence -> hypotheses -> dedupe/critique -> prioritize -> experiment -> update. | Novelty mistaken for truth and unsafe tests; compose with RAG, Prioritization, Guardrails, HITL. |
