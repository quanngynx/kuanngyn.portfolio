# Chapter 4: Offers and Interview Workflow

## Core Idea

Manage the interview as a stateful collaboration and the offer as a multi-dimensional decision. Mistakes, hints, rejection, and negotiation are events to handle deliberately—not verdicts on identity.

## During the Interview

### When an Answer Is Wrong

1. Acknowledge the conflicting case or invariant.
2. Identify whether the defect is in the contract, algorithm, or code.
3. Correct the smallest responsible layer.
4. Recompute complexity if the algorithm changed.
5. Retest the affected boundary and one regression case.

Do not defend a broken approach or silently patch syntax while leaving the invariant wrong.

### When You Have Seen the Problem

Disclose prior exposure. The interviewer can adapt or choose another problem. Concealing it destroys the value of the exercise and creates an integrity risk.

### Choosing a Language

Prefer the language in which you can express common structures, test quickly, and explain behavior accurately. Consider readability to the interviewer and role expectations. Do not select a language solely because it seems impressive.

### When Stuck

- Return to the concrete example.
- State the brute force.
- Recheck unused constraints.
- Apply BUD and BCR.
- Explain what is known and what remains uncertain.
- Treat hints as information and update the plan explicitly.

## Interview-Day Workflow

| Moment | Action |
| --- | --- |
| Before | Confirm logistics, prepare concise project evidence, rest, and avoid last-minute topic overload. |
| Opening | Build rapport and understand the format. |
| Problem | Clarify -> example -> baseline -> optimize -> walk through -> code -> test. |
| Behavioral | Context -> ownership -> decision -> result -> reflection. |
| Candidate questions | Ask about work, ownership, quality, collaboration, and expectations. |
| After | Record questions, mistakes, hints, and process evidence while fresh. |

## Evaluating an Offer

Compare the actual opportunity across dimensions:

| Dimension | Questions |
| --- | --- |
| Role | What decisions and systems will I own? |
| Manager/team | How are feedback, growth, conflict, and quality handled? |
| Learning | Which skills and responsibilities will expand? |
| Product/company | Is the problem meaningful and direction credible? |
| Compensation | Base, bonus, equity terms, benefits, and risk? |
| Lifestyle | Location, hours, travel, flexibility, and sustainability? |
| Trajectory | What does success look like after 6–18 months? |

Avoid collapsing everything into one number before defining personal priorities.

## Negotiation Principles

- Negotiate after understanding the complete package and role.
- Use real alternatives, market evidence, or constraints; do not fabricate leverage.
- Express enthusiasm without surrendering the ability to evaluate.
- Ask which components are flexible.
- Keep communication respectful and specific.
- Review deadlines and equity details carefully.

Historical compensation examples or company practices in the source are not current market guidance.

## Handling Rejection

Record process evidence without inventing a causal explanation. Feedback may be incomplete. Classify controllable weaknesses, schedule a targeted reattempt, preserve professional relationships, and continue the search.

## On-the-Job Transition

An accepted offer starts another learning loop:

1. Clarify expectations and success measures.
2. Map systems, stakeholders, and decision owners.
3. Deliver small verified improvements before broad redesign.
4. Seek feedback early.
5. Keep an evidence log for future project stories.

## Common Mistakes

- Treating one wrong answer as total failure.
- Going silent after a hint.
- Choosing a language whose semantics you cannot explain.
- Evaluating an offer only by brand or headline compensation.
- Fabricating competing offers or deadlines.
- Replaying rejection without converting it into a practice decision.
