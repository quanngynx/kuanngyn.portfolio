## How I Prepared

This section describes the preparation plan I am currently using. It does not claim that I have completed every activity or the full schedule below.

### Aptitude and logic

I am prioritizing quick arithmetic, percentages, ratios, number sequences, letter sequences, logical conditions, and table reading. The goal is not only to solve questions, but also to recognize when skipping one protects time for the rest of the assessment.

### Database design

I am reviewing entities, primary and foreign keys, one-to-many and many-to-many relationships, junction tables, constraints, status fields, and timestamps. Before drawing a schema, I plan to state assumptions briefly and check the edge cases most likely to be overlooked.

The following is a preparation example, not a SystemEXE exercise:

```text title="Practice schema"
users
- id
- name
- email

- unit_price
```

### SQL

I am reviewing `SELECT`, `FROM`, `WHERE`, `GROUP BY`, `HAVING`, `ORDER BY`, `JOIN`, `IN`, and `EXISTS`, followed by aggregates, subqueries, duplicate handling, and `NULL` behavior.

This practice query finds customers with at least three completed orders:

```sql title="Practice aggregate query"
SELECT user_id, COUNT(*) AS completed_orders
FROM orders
WHERE status = 'completed'
GROUP BY user_id
HAVING COUNT(*) >= 3
ORDER BY completed_orders DESC;
```

My approach is to identify the base records, aggregation requirement, and filtering stage before writing syntax. I use a subquery only when it clarifies the requirement or is genuinely necessary.

### Pseudocode

For each pseudocode problem, I plan to state the input, output, assumptions, algorithm, edge cases, and basic time complexity. This practice example filters and then aggregates records:

```text title="Practice pseudocode"
Initialize result as an empty map.

For each record:
  Skip records that do not satisfy the filter.
  Use the requested key to identify the group.
  Add the record value to the group total.

Convert the map into a list.
Sort the list.
Return the result.
```

### Group communication

I am preparing to state assumptions before designing, clarify ambiguous requirements, build on another candidate's suggestion, disagree politely, and reserve time to summarize the final model. A sound design without a clear explanation is still an incomplete answer.

### Original practice questions

I wrote these examples around the skills I want to review. They are not copied from confidential material and are not presented as questions from the SystemEXE test.

**Number sequence:** `3, 7, 15, 31, ?`

Each value is the previous value multiplied by two, plus one. The answer is `63`.

**Letter sequence:** `A, C, F, J, O, ?`

The gaps increase by two, three, four, and five positions. The next gap is six positions, which gives `U`.

**Quantitative estimation:** `What is 15% of 240?`

`10%` is `24` and `5%` is `12`, so the answer is `36`.

**Logical deduction:** An, Binh, and Chi present in different positions. An presents before Binh, and Chi is not first. Which order satisfies both rules?

Chi cannot be first and An must remain before Binh, leaving **An → Chi → Binh** as the only valid order.

## Preparation Checklist

### Before the aptitude test

- Practice without a calculator.
- Use strict time limits.
- Skip questions that exceed the planned time.
- Review common sequence patterns.
- Sleep adequately and arrive early for check-in.

### Before the technical round

- Review basic relational modeling.
- Practice schemas containing two to four tables.
- Write aggregate SQL by hand.
- Review subqueries, joins, duplicates, and `NULL`.
- Explain pseudocode aloud.
- State assumptions before starting.

### Before the group exercise

- Contribute early.
- Listen before rejecting an idea.
- Keep the discussion tied to requirements.
- Track unresolved decisions.
- Reserve time to summarize the design.
- Check the consistency of every relationship.
